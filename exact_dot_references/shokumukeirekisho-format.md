# 職務経歴書 編年体形式フォーマット

## 編年体形式とは

職歴を時系列順（古い→新しい）に記載する形式。キャリアの成長過程が伝わりやすい。
経験年数が浅い人（1〜3年）・初転職・キャリアチェンジ組に最適。

逆編年体は新しい→古い順で、直近の実績をアピールしたい経験豊富な人向け。

## 構成・セクション順序

1. **タイトル**（「職 務 経 歴 書」letter-spacing: 1em、中央揃え）
2. **日付**（右寄せ、「20XX年XX月XX日現在」）
3. **【経歴要約】**（3〜4行。経歴全体を簡潔に要約）
4. **【職務内容】**（編年体＝時系列順）
   - 会社ヘッダ: □20XX年XX月〜現在　○○株式会社
   - 会社メタ: 事業内容：○○　従業員数：○名
   - 期間 / 業務内容の2カラムテーブル（罫線付き）
     - 期間列: 開始年月〜終了年月（縦書き風に改行）
     - 業務内容列:
       - ◆プロジェクト名
       - ◆業務内容（概要文）
       - 【注力した業務】箇条書き（・で列挙、具体的な施策・取り組みレベルで統一）
       - 【技術】使用技術を列挙（遷移は書かない）
       - 【自発的な改善】あれば記載（・で列挙、数値で示す）
5. **【活かせる経験・スキル】**（カテゴリ / スキル の2カラムテーブル、年数は書かない）
6. **【学歴】**（・で列挙）
7. **【資格・活動】**（・で列挙）
8. **【自己PR】**（●強みタイトル + 本文の繰り返し、2〜3点）

## スタイル指針

- 白黒ベースのビジネス文書（背景色・装飾なし）
- テーブルは黒罫線、ヘッダ背景なし
- セクション見出しは【】で囲む
- A4で2枚以内に収める
- 成果は数値で示す（○%短縮、○件など）
- スキル欄に経験年数は書かない（プロジェクト経歴から読み取ってもらう）
- 技術欄に遷移（→）は書かない
- 表記は「BtoC」「BtoB」で統一

## 印刷時の注意

- ブラウザ印刷時「ヘッダーとフッター」のチェックを外す（パス表示を消すため）
- テーブルは行単位で改ページ制御（テーブル全体のpage-break-inside: avoidは使わない）

## エピソード・実績の記述スタイル（調査結果）

### 基本方針

転職エージェント各社（リクルート、JAC、doda、type、ミライトーチ、LevTech等）のSE見本を横断して確認した結果、**「ラベル付きリスト（`経緯:/行動:/結果:`）で見出し分割する形式は標準ではない」**。代わりに以下の二層構造が主流：

1. **担当業務・取り組み** → 箇条書きで列挙（各1行、体言止め）
2. **成果・工夫・アピールポイント** → 短い段落（1〜3文、数値で定量化）

STARは「要素として織り込む」ものであり、「見出しに分ける」ものではない。「一文の結論を先に書き、根拠としてSTARで肉付け」のスタイルが推奨される。

### プロジェクト記述の定型

```
◆プロジェクト名
[1文の概要]。期間 / チーム規模 / 役割を続けて記載。

【注力した業務】
・施策1（体言止め、数値があれば含める）
・施策2
・施策3

【工夫・成果】（任意、短い段落形式）
○○という課題に対し□□を実施、結果△△を達成。
（または箇条書きで数値成果を列挙）

【技術】言語, FW, インフラ...
```

### 各要素の分量目安

| 要素 | 分量 | 形式 |
|------|------|------|
| プロジェクト概要 | 1文（〜50字） | 散文 |
| 担当業務・取り組み | 各1行 × 2〜5項目 | 箇条書き（・） |
| 工夫・成果 | 1〜3文 | 短段落 |
| 技術 | 1行 | 列挙 |

### STARを織り込む書き方の例

背景（S/T）を冒頭1文に凝縮し、行動（A）を箇条書き、結果（R）を末尾1文に置く：

```
◆在庫管理システム機能拡張
物流会社向けに既存システムの機能拡張を担当。客先常駐、要件未確定の状態からスタート。

【注力した業務】
・在庫データ処理バッチの詳細設計・開発・テスト（2ヶ月）
・仕様調整のための顧客折衝

仕様が固まっていない中でも納期通りにリリース完了。
```

（出典: リクルートエージェント、LevTech、リクナビNEXT の SE 見本）

### やってはいけないこと

- `経緯: … / 行動: … / 結果: …` のようなラベル付きリストで各エピソードを書く（冗長・非標準）
- 各項目に常に3要素（経緯・行動・結果）を揃える（重要でないエピソードまで肥大化する）
- 定量化できる成果を散文で曖昧に書く（数値を明示）
