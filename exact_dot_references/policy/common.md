# 共通ポリシー

言語・レイヤー非依存のコーディングルール。

## 外部境界

- システム境界（外部API、ユーザ入力、環境変数、ファイルI/O等）ではバリデーションし、型付きの内部表現に変換する
- 環境変数は起動時にスキーマで検証し、型付きの設定オブジェクトとしてアクセスする。生の `process.env` / `os.environ` 等を内部で直接参照しない
- 内部コード間の受け渡しでは再バリデーションしない。境界で一度変換すれば十分

## 型設計

- 状態を表すフィールドに安易な boolean（`is_deleted`, `is_active` 等）を使わない。状態遷移が増える可能性を考慮し、enum（`status: active | suspended | deleted` 等）で定義する

## コメント

- コメントは「コードから読み取れない制約・意図（why）」のみを書く
- 書かない:
  - 実装詳細のなぞり（次の行が何をするかの説明）
  - 変更履歴（「〜から変更」「以前は〜だった」等。git log の仕事）
  - レビュワー向けの説明（この変更が正しい理由。PR description に書く）
- 既存コードのコメント密度・言語・イディオムに合わせる
