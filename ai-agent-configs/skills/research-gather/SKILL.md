## 手順

### 1. 計画ファイルの読み込み

`docs/.tasks/*.md`（`chain: research`）を読み、現フェーズの未完了タスクを特定する。

### 2. 収集の実行

タスク（調査観点）ごとにサブエージェントを起動し、収集を委譲する。1エージェントが複数観点を担当してもよい。起動時にステータスを `⬜` → `🔵` に更新。

**オーケストレーターは収集しない。** 収集とファイル書き出しを同じエージェントが行うことで、コンテキスト圧縮による消失を防ぐ。

サブエージェントへの指示:

```
以下の観点について調査せよ。
- 調査観点: [タスク内容]
- 出力形式: 事実のリスト。各項目に必ずソースを併記すること（URL、ファイルパス:行番号、ドキュメント名+セクション等）
- 保存先: [エージェントごとに割り当てたファイルパス]
- WebSearch のスニペットを事実として記録するな。スニペットはアクセス先を決めるためのもの。必ず WebFetch でページ本文を読み、本文に記載されている情報のみ記録すること
- 1リソースごとに即ファイルに書き出せ。まとめて書くな。WebFetch → 即追記を繰り返すことで、コンテキスト圧縮による情報の脱落を防ぐ
- ページ内に関連する内部リンク（同一ドメイン）があれば積極的に追え
- ソースのない情報は記録しない。確認できなかった項目は「未確認」と明記する
```

タスク完了時にステータスを `🔵` → `✅` に更新。

### 3. 収集結果のファイル構成

保存先ディレクトリ: `docs/.research/{date}-{topic}/`

エージェントごとにファイルを分ける（競合防止）:

```markdown
# [リソース名]

- 事実1（[ソースURL or ファイルパス:行番号]）
- 事実2（[ソースURL or ファイルパス:行番号]）
```

## 次のスキル

→ **research-write** を呼べ。収集結果ファイルのパスを引き継ぐ。
