# Core Protocols

## デバッグプロトコル

### 発動条件

- エラーやバグの報告
- コードが期待通りに動かない
- ビルド/テスト失敗
- スタックトレースやエラーメッセージの出現

### 必須シーケンス

**Step 1-2 を完了するまで解決策を提案してはならない。**

#### Step 1: 調査

orchestrate-research スキルに従ってリソースにアクセスする。
エラータイプ別テーブルで最初のアクションを決定し、調査の方向を定める。

| エラータイプ | 最初のアクション |
|-------------|-----------------|
| ライブラリ/APIエラー | ctx7 CLI（`ctx7 docs`）or 公式ドキュメント |
| ランタイムエラー | WebSearch（正確なエラーメッセージ + バージョン） |
| ビルドエラー | バージョン・設定確認 |
| 型エラー | 型定義を Read |
| インポートエラー | パッケージインストール確認 |

#### Step 2: 分析

```
1. 症状ではなく根本原因を特定
2. バージョン互換性を確認
3. 問題を切り分け
4. 破壊的変更の CHANGELOG を確認
```

#### Step 3: 解決策の提示

```
1. 解決策のソースを明記
2. 不確実な場合は代替案を提示
3. 検証コマンドを含める
```

修正が必要な場合は orchestrate-coding の実装・レビューサイクルに入る。

## アンチパターン（禁止）

- 調査せずに解決策を提案する
- 似たようなエラーからの推測で回答する
- 検証コマンドを省略する
- バージョン情報を無視する
