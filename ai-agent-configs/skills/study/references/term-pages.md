# 単語ページ (term/)

note と並列に `term/` 配下の単語ページとして作成する（Scrapbox 風に単語間を相互リンク）。ノート構造・タグ規約・フェーズ構成は通常の study ノートと同じ。

## トリガー

ユーザが単語に明示言及したときのみ作成（Claude から自発的に作らない）。

- ✅ 単発の用語質問: 「Mutex って何？」「CAP定理の定義は？」
- ✅ 派生質問で単語名が明示: 「TCP の話に出てくる Slow Start も知りたい」
- ❌ 単語名が出ない曖昧な要求: 「難しい概念があるけど何？」「ここを詳しく」

## パス

```
term/{word-slug}.md
```

- `word-slug` = kebab-case。日付プレフィックスなし
- 例: `term/mutex.md`

## 同名衝突（辞書方式）

異なる語義が衝突したら、新ファイルを作らず同一ファイル内に `## {分野ラベル}` で並べる。ラベルは frontmatter の `topic/*` `tech/*` と整合させる。

```markdown
# python

## プログラミング言語
...（概要・詳細・参考をこの下にぶら下げる）

## ギリシャ神話
...
```

### 分野ラベルの粒度

- 異なる領域なら分割（プログラミング言語 vs ギリシャ神話、統計学 vs 機械学習）
- 同一領域内の細かい用法差では分割しない
- 迷ったら分割しない（統合は破壊的、後からの分割は容易）

### tag のマージ

frontmatter の tags は全語義の `topic/*` `tech/*` を合算。

## 作成手順

1. `obsidian read path="term/{slug}.md"` で存在確認
2. 既存あり → `obsidian append` で新語義セクションを追加。tags は既存とマージして `obsidian replace` で更新
3. 既存なし → `obsidian create` で新規作成

## リンクの貼り方

term ページ作成・更新時:

1. `ls term/` または `obsidian search` で既存 term ページ一覧を取得
2. 新ページ本文に出現する単語を一覧と照合
3. マッチしたものを `[[term/word]]` リンク化
4. 親 study ノートから派生した場合、親ノートにも `[[term/word]]` を 1 箇所追加して逆リンクを張る

全文書を遡及してリンク化はしない（爆発するため）。

## セルフチェック (term ページ作成時)

- 同名衝突を `obsidian read` で確認し、衝突時は辞書方式で追加したか
- frontmatter tags は全語義分マージできているか
- 本文の既知 term への `[[term/word]]` リンク化と、親ノートからの逆リンクを張ったか
