## リソース列挙

| 調査対象 | 方法 |
|----------|------|
| ライブラリ・API仕様 | ctx7 CLI（最優先）→ WebSearch にフォールバック |
| 技術的事実 | 公式ドキュメント or WebSearch |
| 一般的事実 | WebSearch |
| ファイル内容 | Read |
| コードの挙動 | Read + トレース |

### ctx7 CLI の使い方

ライブラリ・API のドキュメントを取得する CLI ツール。MCP サーバーではない。

```bash
# 1. ライブラリ ID を検索
ctx7 library "react" "hooks usage"

# 2. ドキュメントを取得
ctx7 docs /facebook/react "useEffect cleanup"
```

ctx7 が利用できない環境では WebSearch にフォールバックする。

## 並列アクセス

リソースが5つ以上の場合、サブエージェントを並列起動してアクセスする。
5つ未満の場合は自分で直接アクセスする。
サブエージェントはサブエージェントを呼び出せないため、並列アクセスは常にオーケストレーターが起動する。

- **Web**: サブエージェントを並列起動し WebFetch
- **ローカル**: Read / Grep を同一ターンで並列呼び出し
- **混在**: 同時実行

サブエージェントへの指示:

```
以下のリソースにアクセスし、[調査テーマ] に関連する情報を抽出せよ。
- リソース: [URL or ファイルパス]
- 抽出すべき情報: [具体的な観点]
- 出力: 事実のリスト（各項目にソースの該当箇所を併記）
- 結果の保存先: [ファイルパス]
```

## ドキュメント作成

調査結果が意思決定に影響する場合はドキュメント化する。
リソースが5つ以上の場合、段階ごとにサブエージェントを分離する。

```
├── investigation エージェント
│   収集結果を読み、調査ドキュメントを作成
│
├── consideration エージェント
│   調査ドキュメントを読み、検討ドキュメントを作成
│
└── decision エージェント
    検討ドキュメントを読み、決定ドキュメントを作成
```

ユーザーの要求が調査のみなら investigation まで、検討までなら consideration まで。

各エージェントには「documentation スキルに従ってドキュメントを作成せよ」と指示する。
入力（前段階ドキュメント or 収集結果）と出力先を明示する。

## 品質レビュー

- サブエージェントの成果物は必ずレビューしてからユーザーに返す
- 不十分な場合は具体的なフィードバックを添えて再委譲する
