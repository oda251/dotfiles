# バックエンドアーキテクチャ

## FC/IS (Functional Core / Imperative Shell)

- ビジネスロジック（Core）は純粋関数で書く。副作用・I/O を持たない
- 副作用（DB, API, ファイル等）は外殻（Shell）に押し出す
- Shell が入力を受け取り、Core を呼び、結果に基づいて副作用を実行する
- Core は単体テストだけで検証できる。Shell は統合テストで検証する

## データモデルと DTO

- DTO を明確に定義する
- モデル層（DB スキーマ等）を SSOT とし、DTO はモデルから派生させる
- モデルと DTO を独立に定義しない。モデルの変更が DTO に自動的に反映される設計にする
