# エージェントアーキテクチャ

AI エージェントの責務分離と構成。

## 3層構造

```
hooks/       → ルーティング（セッション開始時の振り分け）
dispatch/    → オーケストレーション（いつ・どの順で実行するか）
skills/      → 行動定義（何をどうやるか）
references/  → コーディング規約・技術スタック（言語横断の共通ルール）
```

### hooks（ルーター）

- セッション開始時に読み込まれるブートストラップ
- ユーザー指示を解釈し、dispatch に渡すか直接対応するかを判断する
- スキルではない（ワークフローを持たない）

### dispatch（オーケストレーター）

- タスクの登録・依存関係（DAG）・実行順序を管理する
- **何をやるか（行動）には関与しない**。スキルに委譲する
- Claude Agent SDK `query()` でサブエージェントを起動し、`settingSources: []` でフック・設定の漏洩を防ぐ
- タスクタイプとスキルの対応はスキルのフロントマター `task-types` から動的に解決する

### skills（行動定義）

- 各スキルは `SKILL.md` にフロントマターと実行指示を持つ
- フロントマターの `task-types` フィールドで、dispatch のタスクタイプとバインドする
- ワークフロー（TDD の適用判断、セルフチェック、エスカレーション等）はスキル内に記述する
- コーディング規約はスキルに書かない。references を参照する

### references（コーディング規約）

- 言語・フレームワーク固有のコーディングルール
- テストガイドライン、型安全の方針等
- スキルから `~/.claude/references/{lang}.md` として参照される
- ワークフローは書かない（それはスキルの責務）

## サブエージェント設計

```ts
query({
  prompt,
  options: {
    settingSources: [],  // CLAUDE.md・フックの漏洩を防ぐ
    systemPrompt: { type: "preset", preset: "claude_code" },
    allowedTools: [...],
  },
})
```

- `settingSources: []` により、親のコンテキスト汚染を排除
- システムプロンプト（~23K tokens）はSDKでもCLIでも同量ロードされる。SDKの利点はプロセス起動コスト・フック再発火の回避
- スキル内容はプロンプトに直接注入する（サブエージェントはスキルファイルを読まない）
