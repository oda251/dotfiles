学習を Q&A セッションとして進め、vault に学習ノートとして蓄積する。ユーザの合図でクイズを実施する。

## 適用範囲

| トリガーする | しない |
|---|---|
| 「Reactのレンダリングの仕組みを教えて」 | 「このSvelteKitプロジェクトのrendering modeどう設定してる？」 |
| 「JWTってどう動くの？」 | 「この repo のauth middlewareの流れ追って」 |
| 「CAP定理って？」 | 「我々のDB構成のトレードオフを整理して」 |

判断基準は「同じ説明が別のプロジェクトの読者にもそのまま価値を持つか」。ハイブリッドの場合は一般部分のみノート化し、プロジェクト固有の話は会話に留める。

## 前提

ドキュメント作成・更新の共通規約は docs skill に従う。

### 学習ノート固有の追加規約

学習ノートは横断検索する前提なので、docs skill のタグに加えて以下を必須にする:

- `purpose/study`
- `ndc/*`（技術関連ノートはさらに `tech/*` と `ccs/*`）

パスの `title` 部分は学習テーマの kebab-case slug（例: `tcp-congestion-control`）。単語への明示言及時は `term/{word-slug}.md`（詳細: `references/term-pages.md`）。

## フェーズ構成

```
[1] 初回質問への回答 + ノート作成
        ↓
[2] 追加質問ループ（性質に応じて QA 追記 / 本文更新 / 両方）
        ↓ ユーザの「クイズ」「テスト」等の合図
[3] 記述式クイズによる理解確認
```

ユーザが単語に明示言及した場合は [1]/[2] と並行して term/ ページを作成する。詳細は `references/term-pages.md`。

## [1] 初回回答 + ノート作成

ユーザの質問に簡潔に答えてから、ノートを作成する。

### 本文構造

```markdown
# {タイトル}

> 学習開始: {date}

## 概要
{要点}

## 詳細
{セクション分け。コード例・mermaid 図}
```

`## QA` のようなラッパーは置かない。追加質問は `### Q: ...` を末尾に直接 append する。

## [2] 追加質問ループ

追加質問は性質を分類してから反映する:

| 質問の性質 | 例 | 反映先 |
|---|---|---|
| (A) 概念に関する新規質問 | 「Slow Start と Congestion Avoidance の違いは？」 | 末尾に `### Q: ...` で追記 |
| (B) 本文の記述に対する質問/疑問 | 「『閾値』って具体的に何の値？」「ここの説明があいまい」 | 本文の該当箇所を更新（明確化・補強・訂正） |
| (C) 両方の性質を持つ | 概念質問だが、答えると本文の弱い部分が露呈する | (A) と (B) の両方 |
| (D) 本文に要改善事項が発覚 | 回答中に本文の誤り・抜け漏れに気付いた | 本文を更新（QA追記は質問次第） |

### QA 追記 (A/C)

`obsidian append` で `### Q: {要約}` 見出しと回答本文を末尾に追記する。

### 本文更新 (B/C/D)

`obsidian read` で確認 → `obsidian replace` で該当箇所を更新（大きな書き換えはセクション単位で置換）。本文中に「追記:」「訂正:」などのメタ注釈は残さない（ノートは最終状態）。

## [3] クイズフェーズ

### 起動条件

ユーザの明示的合図でのみ起動する。合図例: 「クイズ」「クイズして」「テスト」「確認テスト」「理解度チェック」「quiz」「test」

### 進め方

1. 出題数（デフォルト 3 問）、出題範囲（デフォルト ノート全体）をユーザに確認
2. 記述式で 1 問ずつ出題
3. ユーザの回答に対し:
   - 模範解答と照合し、合致点・不足点・誤りを指摘
   - 答えられなかった項目はノートが弱い可能性が高い。フェーズ 2 の (D) と同じ扱いで本文を更新する
4. 全問終了後、総評（強い領域 / 弱い領域 / 復習推奨セクション / ノート改善の要約）

### 出題の質

- 暗記より理解を問う（「なぜ」「いつ使うか」「他との違い」）
- 範囲はノート本文に限定

## セルフチェック

完了前に確認:

- 追加質問の性質分類 (A/B/C/D) に従って反映したか
- クイズはユーザの明示合図で起動したか
- クイズで露呈した弱点をノートに反映したか
- term ページを扱った場合は `references/term-pages.md` のセルフチェックも実施したか
