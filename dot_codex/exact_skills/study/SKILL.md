学習を Q&A セッションとして進め、vault に学習ノートとして蓄積する。ユーザの合図でクイズを実施する。

## 適用範囲

判断基準は「同じ説明が別プロジェクトの読者にも価値を持つか」。ハイブリッドの場合は一般部分のみノート化し、プロジェクト固有の話は会話に留める。

## 前提

docs skill のドキュメント規約に従う。学習ノート固有の追加規約:

- 必須タグ: `purpose/study`, `ndc/*`（技術関連は `tech/*` と `ccs/*` も）
- パスの `title` 部分は学習テーマの kebab-case slug（例: `tcp-congestion-control`）
- 単語への明示言及時は `term/{word-slug}.md`（詳細: `references/term-pages.md`）

## [1] 初回回答 + ノート作成

ユーザの質問に簡潔に答えてから、ノートを作成する。本文は高コンテキスト表現で圧縮し、各セクションを薄く保つ（深掘りは追加質問に委ねる）。関連用語はその場で展開せず、ユーザが質問してきた時に term ページに切り出す。

### 本文構造

```markdown
# {タイトル}

> 学習開始: {date}

## 概要
{要点}

## 詳細
{セクション分け。コード例・mermaid 図}
```

追加質問は `### Q: ...` を末尾に直接 append する（`## QA` のラッパーは置かない）。

## [2] 追加質問ループ

追加質問は性質を分類してから反映する:

| 質問の性質 | 例 | 反映先 |
|---|---|---|
| (A) 概念に関する新規質問 | 「Slow Start と Congestion Avoidance の違いは？」 | 末尾に `### Q: ...` で追記 |
| (B) 本文の記述に対する質問/疑問 | 「『閾値』って具体的に何の値？」 | 本文の該当箇所を更新 |

(C) 両方の性質を持つ場合は両方適用。(D) 回答中に本文の誤り・抜け漏れに気付いた場合は本文を更新。

`obsidian append` で QA 追記、`obsidian read` → `obsidian replace` で本文更新（大きな書き換えはセクション単位）。本文に「追記:」「訂正:」などのメタ注釈は残さない。

## [3] クイズフェーズ

### 起動条件

ユーザの明示的合図でのみ起動。合図例: 「クイズ」「テスト」「確認テスト」「理解度チェック」「quiz」「test」

### 進め方

1. 出題数（デフォルト 3 問）、出題範囲（デフォルト ノート全体）をユーザに確認
2. 記述式で 1 問ずつ出題
3. 回答を模範解答と照合し、合致点・不足点・誤りを指摘。答えられなかった項目は (D) として本文を更新
4. 全問終了後、総評（強い領域 / 弱い領域 / 復習推奨セクション / ノート改善の要約）

### 出題の質

- 暗記より理解を問う（「なぜ」「いつ使うか」「他との違い」）
- 範囲はノート本文に限定
