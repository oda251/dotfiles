メイン（PM）は要件設計・進行管理・赤緑判定・push のみを担当し、テスト作成は `test-writer`、実装は `implementer` サブエージェント（いずれも兄弟起動）に委譲する。フェーズ間の受け渡しは要件ファイルとファイルパスに限定し、メインのコンテキストを薄く保つ。

## 手順

1. `main` を基点に worktree を作り、要件ファイル `$WT/docs/tmp/<slug>.md` を用意する
   - 求める振る舞いを mermaid で表現する（適切なグラフタイプを選ぶ）
   - プロジェクト固有でない細かな例外処理は mermaid に含めず、手順 2 のチェックリストで示す
2. 要件をテスト可能なアサーション（入力 → 期待）に分解し、要件ファイルにチェックリストで書く。1項目 = テスト1つの粒度
3. 不足観点（異常系・境界・非機能・IF）を `AskUserQuestion` で詰め、要件ファイルを確定する
4. 要件を1つずつ消化する（複数同時着手しない）。各要件で:

   1. テストを書くか判断する: `テストを書く = ( expect(fn(input)).toBe(output) が書ける ) && ( ビジネスロジックに関わる )`
   2. 書くなら `test-writer` エージェントに worktree 絶対パス・要件ファイルパス・対象項目を渡し、赤テストを1本書かせる。返ってきた実行コマンドでメインが赤を再確認する
   3. `implementer` エージェントに worktree 絶対パス・テストファイルパス・本タスクに関連する `~/.references` ガイドラインのパスを渡し、最小実装をさせる。バックグラウンドで実行する
   4. メインが検証する。テストを書いたなら対象テスト緑 + テスト未改変（`git diff` でテストファイルに変更がないこと）を確認、書かないなら振る舞いを直接確認
   5. commit する
5. 全要件 green になったら `/simplify` → 全体テスト緑を再確認する
6. push して draft PR を作成（PR body は要件ファイル）。一時ファイルは消す。draft のまま完了報告する

test-writer が基盤未整備（シードデータ・テスト環境構築等）で赤テストを書けないと報告したら中断し、進め方をユーザと相談する。
