## トリガー

test-writing から遷移してきたとき。

## エージェント構成

実装者のバイアスを避けるため、レビュアーは別エージェント。小規模タスクでは自分でレビューしてよい。

## 手順

**レビュアー**がテストをレビューする:

```
以下のテストをレビューせよ。
- テストファイル: [ファイルパス一覧]
- テスト対象の振る舞い: [何をテストしているか]
- 観点: 網羅性（正常系・異常系・境界値）、テストの妥当性、過不足
- 問題があれば具体的な修正案を示すこと
```

指摘があれば実装者が修正する。

### レビューループの上限

最大 3 回まで。3 回を超えた場合はユーザーに状況を報告し、判断を仰ぐ。

## 次のスキル

→ **implementation** を呼べ。テストファイルのパスとタスク定義を引き継ぐ。
