# Core Protocols

## デバッグプロトコル

### 発動条件

- エラーやバグの報告
- コードが期待通りに動かない
- ビルド/テスト失敗
- スタックトレースやエラーメッセージの出現

### 必須シーケンス

**Step 1-2 を完了するまで解決策を提案してはならない。**

#### Step 1: SEARCH FIRST

```
1. 正確なエラーメッセージを抽出
2. WebSearch: "[エラーメッセージ] [言語/フレームワーク] [バージョン]"
3. ライブラリ関連なら ctx7 docs で確認
4. GitHub Issues / Stack Overflow を確認
```

#### Step 2: ANALYZE

```
1. 症状ではなく根本原因を特定
2. バージョン互換性を確認
3. 問題を切り分け
4. 破壊的変更の CHANGELOG を確認
```

#### Step 3: VERIFIED SOLUTION

```
1. 解決策のソースを明記
2. 信頼度レベルを宣言
3. 不確実な場合は代替案を提示
4. 検証コマンドを含める
```

### エラータイプ別クイックリファレンス

| エラータイプ | 最初のアクション |
|-------------|-----------------|
| ライブラリ/APIエラー | ctx7 docs or 公式ドキュメント |
| ランタイムエラー | WebSearch（正確なメッセージ） |
| ビルドエラー | バージョン・設定確認 |
| 型エラー | 型定義を Read |
| インポートエラー | パッケージインストール確認 |

## 信頼度レベル

| レベル | 基準 | アクション |
|--------|------|------------|
| **HIGH** | ツールで確認済み、2つ以上のソース | ソースを明記 |
| **MEDIUM** | 単一ソース、部分的検証 | 注意書きを追加 |
| **LOW** | 記憶のみ、未検証 | 明示的に警告 |
| **UNKNOWN** | 評価不能 | 「わかりません」と明言 |

## アンチパターン（禁止）

- 検索せずに解決策を提案する
- 似たようなエラーからの推測で回答する
- 信頼度レベルを省略する
- 検証コマンドを省略する
- バージョン情報を無視する
