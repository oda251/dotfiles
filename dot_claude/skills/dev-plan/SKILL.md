## 手順

### 0. 準備

対象言語・フレームワークに対応するガイドラインがあれば読む:
- `~/.claude/references/{lang}.md`（例: `ts.md`）
- `~/.claude/references/{lang}-{framework}.md`（例: `ts-react.md`）

フレームワークは設定ファイル（next.config, svelte.config, hono 等）から判定する。

新規実装や設計判断を伴う変更では、計画の前に research-planning を呼んでベストプラクティス・既存コードのパターン・ライブラリの推奨用法を調べる。
既存コードの軽微な修正（バグ修正、リネーム等）ではスキップしてよい。

### 1. フェーズ分割

大きなタスクは依存関係に基づいてフェーズに分割する。

後続フェーズが前のフェーズの成果物に依存する場合、必ず別フェーズにする。
1サイクル内の依存順整理（先にAを実装してからBを実装）で済む場合はフェーズ分割不要。
単一フェーズで完結するタスクではフェーズ分割は不要。

### 2. タスク分解と分類

タスクを2種類に分類する:

| 種類 | 例 | 進め方 |
|------|-----|--------|
| **セットアップ** | ライブラリ導入、ディレクトリ構成、設定ファイル、型定義の初期設計 | implementation → implementation-review |
| **振る舞い** | ビジネスロジック、API、データ変換、バリデーション | tdd-impl（TDD サイクル）→ implementation-review |

- 変更対象ファイルを列挙する
- ファイル間の依存関係を整理し、並列実行可能な単位に分割する
- 共有するインターフェース（型定義、API 契約等）を先に確定する
- 要件不明確・設計判断が分かれる場合はユーザーに確認。推測で実装しない

### 3. 計画の永続化

タスク一覧をチェックリスト形式でファイルに書き出す。

保存先: `docs/plans/{date}-{topic}.md`

```markdown
## タスク

- [ ] [setup] ライブラリ導入（express, zod）
- [ ] [setup] ディレクトリ構成作成
- [ ] [tdd] ユーザー登録 API
- [ ] [tdd] バリデーション
```

### 4. タスク消化ループ

計画ファイルを読み、未完了タスク（`- [ ]`）を先頭から順に実行する:

1. タスクの種類に応じてスキルを呼ぶ:
   - `[setup]` → **implementation** を呼べ
   - `[tdd]` → **tdd-impl** を呼べ
   - サブエージェント指示に、準備で特定したガイドラインのパスを含めること
2. implementation-review 完了後、計画ファイルのタスクを `- [x]` に更新する
3. 計画ファイルを再読み込みし、次の未完了タスクに進む
4. 全タスクが `- [x]` になったら完了
