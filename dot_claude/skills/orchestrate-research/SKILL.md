# Orchestrate: 調査・検討・意思決定

## 規模の判断

```
調査リソースの数
├── 5つ未満 → 自分で完結。documentation スキルに従いドキュメントを書く
└── 5つ以上 → 以下のエージェント分離フローを実行
```

## エージェント分離フロー

サブエージェントはサブエージェントを呼び出せないため、並列アクセスはオーケストレーターが直接行う。

```
├── Step 1: リソース列挙
│
├── Step 2: 並列アクセス（サブエージェント群）
│   結果はファイルに書き出す
│
├── Step 3: investigation エージェント
│   収集結果を読み、調査ドキュメントを作成
│
├── Step 4: consideration エージェント
│   調査ドキュメントを読み、検討ドキュメントを作成
│
└── Step 5: decision エージェント
    検討ドキュメントを読み、決定ドキュメントを作成
```

ユーザーの要求が調査のみなら Step 3 まで、検討までなら Step 4 まで。

### リソース列挙（Step 1）

| 調査対象 | 方法 |
|----------|------|
| ライブラリ・API仕様 | ctx7（最優先）→ WebSearch にフォールバック |
| 技術的事実 | 公式ドキュメント or WebSearch |
| 一般的事実 | WebSearch |
| ファイル内容 | Read |
| コードの挙動 | Read + トレース |

### 並列アクセス（Step 2）

- **Web**: サブエージェントを並列起動し WebFetch
- **ローカル**: Read / Grep を同一ターンで並列呼び出し
- **混在**: 同時実行

### ドキュメント作成エージェント（Step 3〜5）

各エージェントには「documentation スキルに従ってドキュメントを作成せよ」と指示する。
入力（前段階ドキュメント or 収集結果）と出力先を明示する。

## 品質レビュー

- サブエージェントの成果物は必ずレビューしてからユーザーに返す
- 不十分な場合は具体的なフィードバックを添えて再委譲する
