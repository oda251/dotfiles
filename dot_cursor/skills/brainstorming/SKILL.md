name: brainstorming
description: 「Xを作りたい」「Xを実装して」など構築・設計タスクで使う。対話で要件を引き出し、設計方針を合意してから実装に進む。要件が曖昧なとき、設計判断が必要なときは必ず使うこと。
---

## 手順

### 1. 要件の引き出し

思考パートナーとして対話する:

- まず動機を聞く（何を達成したいか、なぜか）
- エネルギーがある方向に掘り下げる
- 曖昧さには具体例で返す
- 一度に多くを聞かない。1つずつ質問する
- 選択肢がある場合は具体的な選択肢を提示する
- ゴール、制約条件、スコープ（何をやらないか）を明らかにする

### 2. 合意

ユーザーが方針を承認してから次に進む。
推測で実装しない。

### 3. タスクファイル作成

合意した内容を root タスクファイルに書き出す。

保存先: `docs/.tasks/{date}-{topic}.md`

```markdown
## 背景
既存のセッション認証から JWT に移行したい。移行中も既存セッションを切りたくない。

## ゴール
- JWT ベースの認証 API
- 既存セッションとの並行稼働期間

## 制約
- Express + TypeScript
- 既存の connect-redis セッションストアは残す

## タスク

| ステータス | 表記 |
|-----------|------|
| 未着手 | `⬜` |
| 実行中 | `🔵` |
| 完了 | `✅` |

### Phase 1: plan-research
- ⬜ a. JWT / Session / OAuth の認証パターン比較

### Phase 2: plan-dev
- ⬜ a. 認証機能の設計・実装
```

タスクは具体的に書く。「ベストプラクティス調査」のような曖昧な記述は避ける。
調査不要なら plan-research フェーズは省略してよい。

## 次のスキル

→ **plan** を呼べ。タスクファイルのパスと最初のフェーズ番号を引き継ぐ。
