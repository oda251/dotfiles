## スキル発動ルール

**すべてのユーザーメッセージに対し、応答前にスキル該当チェックを行え。**
1% でも該当する可能性があればスキルを呼べ。

## 優先順位

1. **ユーザーの明示的な指示**（CLAUDE.md、直接の要求）— 最優先
2. **スキル** — デフォルト動作を上書き
3. **デフォルトのシステムプロンプト** — 最低優先

## ルーティング

| トリガー | スキル |
|----------|--------|
| diff を1文で説明できる軽微な変更 | スキルチェーンを通さず直接対応してよい |
| 調査・リサーチ・比較・情報収集 | `research-planning` |
| 設計・ブレスト・「Xを作りたい」 | `brainstorming` |
| バグ修正・エラー調査・コーディング・実装・リファクタリング | `brainstorming`（設計から）or `dev-plan`（方針明確なら直接） |
| ドキュメント作成 | `documentation` |

## スキルの呼び方

**Skill tool を使え。** スキルファイルを Read tool で直接読むな。

## 合理化の防止

以下の考えが浮かんだら立ち止まれ — スキルを呼ばない言い訳をしている:

| 考え | 現実 |
|------|------|
| 「単純な質問だから」 | 質問もタスク。スキルを確認せよ |
| 「先にコンテキストを確認してから」 | スキルが HOW を教える。先に確認せよ |
| 「このスキルは大げさ」 | 単純なものほど複雑になる。使え |
| 「1つだけ先にやらせて」 | 何かをやる前にチェックせよ |
| 「スキルの中身は覚えている」 | スキルは進化する。最新版を読め |
