## エージェント構成

実装者のバイアスを避けるため、レビュアーは別エージェント。

## 手順

**レビュアー**がテストをレビューする:

```
以下のテストをレビューせよ。
- テストファイル: [ファイルパス一覧]
- テスト対象の振る舞い: [何をテストしているか]
- 観点:
  1. 網羅性: 正常系・異常系・境界値がカバーされているか
  2. 妥当性: テスト対象自体を mock していないか、アサーションが実装の振る舞いを検証しているか
  3. 信頼性: ネットワーク依存で flaky にならないか、テスト依存の境界（test-writing の表）に従っているか
  4. 過不足: 不要なテストや重複がないか
- 問題があれば具体的な修正案を示すこと
```

指摘があれば実装者が修正する。

### レビューループの上限

最大 3 回まで。3 回を超えた場合はユーザーに状況を報告し、判断を仰ぐ。

## 次のスキル

→ **implementation** を呼べ。テストファイルのパスとタスク定義を引き継ぐ。
