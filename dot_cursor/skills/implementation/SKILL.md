## 手順

**実装者**がテストを通す実装を行う。実装者はテスト作成と同じエージェントでよい（コンテキストを共有するため）。

```
以下のファイルを変更せよ。
- 対象: [ファイルパス]
- 変更内容: [具体的な指示]
- 守るべきインターフェース: [型定義や API 契約]
- 対応するテスト: [テストファイルパス]
- 既存のコードスタイルに従うこと
```

並列実装時は、共有リソース（同一ファイルへの同時書き込み等）の競合を避ける。

implementation-review から戻ってきた場合は、レビュー指摘を反映して修正する。
原因不明のエラーが発生した場合は research-planning で調査してから対処する。

## 次のスキル

→ **implementation-review** を呼べ。変更ファイル一覧を引き継ぐ。
