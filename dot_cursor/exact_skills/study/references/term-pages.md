# 単語ページ (term/)

note と並列に `term/` 配下に作成（Scrapbox 風に相互リンク）。本文構造・タグ規約・フェーズ構成は通常の study ノートと同じ。

## トリガー

ユーザが単語に明示言及したときに作成する。

- 単発の用語質問: 「Mutex って何？」「CAP定理の定義は？」
- 派生質問で単語名が明示: 「TCP の話に出てくる Slow Start も知りたい」

## パス

`term/{word-slug}.md`（kebab-case、日付プレフィックスなし）。例: `term/mutex.md`

## 同名衝突（辞書方式）

異なる語義が衝突したら、新ファイルを作らず同一ファイル内に `## {分野ラベル}` で並べる。ラベルは frontmatter の `ndc/*` `ccs/*` `tech/*` と整合させる。

```markdown
# python

## プログラミング言語
...

## ギリシャ神話
...
```

粒度: 異なる領域なら分割（プログラミング言語 vs ギリシャ神話）、同一領域内の細かい用法差では分割しない。迷ったら分割しない（統合は破壊的、後からの分割は容易）。

frontmatter の tags は全語義分を合算（study skill のタグ規約を語義ごとに適用してから OR を取る）。

## 作成手順

1. `obsidian read path="term/{slug}.md"` で存在確認
2. 既存あり → `obsidian append` で新語義セクションを追加。tags は既存とマージして `obsidian replace` で更新
3. 既存なし → `obsidian create` で新規作成

## リンクの貼り方

term ページ作成・更新時:

1. `ls term/` または `obsidian search` で既存 term ページ一覧を取得
2. 新ページ本文に出現する単語を一覧と照合
3. マッチしたものを `[[term/word|word]]` 形式でリンク化（エイリアス必須）
4. 親 study ノートから派生した場合、親ノートにも `[[term/word|word]]` を 1 箇所追加して逆リンクを張る

全文書を遡及してリンク化はしない（爆発するため）。

## セルフチェック (term ページ作成時)

- 同名衝突は辞書方式で統合されているか
- frontmatter tags は全語義分マージできているか
- 本文の既知 term へリンクを張ったか / 親ノートからの逆リンクを張ったか
