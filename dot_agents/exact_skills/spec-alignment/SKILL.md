# 仕様合意

ユーザーから見える振る舞いを決めるとき、設計・実装に先立って使う。動作に影響しない変更には不要。

## 手順

1. 依頼や関連資料から根拠を確認し、明記された仕様、ユーザーの決定、未解決点を区別する。現行実装やテストだけを新しい振る舞いの根拠にしない。
2. 仕様の説明と確認にはD2図を用い、外から観察できる振る舞いを簡潔な文章とともに示す。
3. `d2 --watch --browser=0 <model.d2>` でレビュー用のdevserverを起動し、ユーザーの指摘を仕様と図に反映する。振る舞いに関わる点が合意されるまで、設計や実装に進まない。レビュー後はdevserverを停止する。
4. 合意した仕様を対象Issueの本文に記載し、D2のSVGとソース（折りたたみ節）を含める。後から仕様を変更するときもコメントを追加せず、同じIssue本文を更新する。本文の更新には `gh issue edit <number> --body-file <body.md>` を使う。
5. 合意後に内部設計が必要なら、`design-alignment` に引き継ぐ。
