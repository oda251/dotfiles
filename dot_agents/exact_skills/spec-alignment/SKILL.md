# 仕様合意

実装方法を議論する前に、外から観察できる振る舞いを合意する。このスキルは manager/administrator agent が使用する。成果物はユーザーがレビューできる簡潔な概念モデルであり、本番コード、テスト一式、想定可能なケースの網羅リストではない。

仕様の説明とユーザーによる確認は、必ずD2図を用いて行う。

## 使う場面

- ユーザーから見える振る舞いが変わる機能・変更。
- 要件や例から複数の解釈が成り立つとき。
- ユーザーが仕様のモデル化・レビューを求めたとき。

振る舞いに影響しない変更（誤字修正など）では使わない。設計を検討する場合は、振る舞いモデルの承認後に [`design-alignment`](../design-alignment/SKILL.md) へ進む。

## 手順

1. **仕様の根拠を集める。** 利用可能な中で最も低コストの適切なサブエージェントに、読み取り専用で根拠調査を委譲する。ユーザーの依頼と調査対象の場所を渡し、次を報告させる。
   - 根拠となる正確なパス・節と、短い引用。
   - 明記された例、制約、権威ある資料同士の矛盾。
   - 依頼された振る舞いのうち、根拠が見つからないもの。

   調査エージェントは事実を集めるだけで、意図の決定、要件の創作、ファイル編集をしない。ユーザーの依頼と明示的な決定も根拠として扱う。新しい振る舞いの根拠として、実装詳細や既存テストを使わない。

2. **振る舞いの概念モデルを書く。** 短い自然言語の説明とD2図を作る。フロー、相互作用、状態遷移、データモデルなど、振る舞いの理解に必要な視点をD2で表す。仕様の説明・レビューに関わる図はすべてD2を使う。Mermaidは使わない。

   入力、重要な判断や変換、観察可能な結果を示す。実装コンポーネント、クラス名、メソッド名はこのモデルに含めない。必要な振る舞い判断を説明できる最小の抽象度から始め、必要な箇所だけ詳細化する。

3. **エッジケースを絞る。** 根拠に明記された例外、振る舞いが変わる境界、契約上重要な失敗、ユーザーが明示したケースだけを短い表にする。条件、観察可能な結果、根拠または状態（`仕様に明記` / `ユーザー決定` / `未解決`）を記録する。推測を要件にしたり、細部で図を埋めたりしない。

4. **ユーザーとレビューする。** `mise exec -- d2 --watch --browser=0 <model.d2>` でD2 devserverを起動し、URLをユーザーに示す。必要に応じて `openurl <URL>` でブラウザーに表示する。振る舞いモデル、根拠、判断に必要な未解決点を説明し、対話中の訂正をD2ソースへ反映する。振る舞いに影響する点が承認されるまで、設計、テスト作成、実装へ進まない。レビューが終わったらdevserverを停止する。

   複雑な図は関心事ごとに分割し、短い説明や表を添える。大きな図を一枚に押し込まず、レビューに不要な詳細や例外は省く。必要な箇所だけ詳細化する。

5. **承認済み仕様をIssue本文に維持する。** 承認済みの仕様が属するGitHub Issueの本文を、承認済みの自然言語仕様とD2モデルで更新する。Issue番号またはURLを引き継ぎ、コメントではなくIssue本文そのものを更新する。

   `gh issue edit <number> --body-file <body.md>` を使う。本文にはD2 SVGを画像として掲載し、D2ソースは折りたたみ可能な `<details>` 節のコードブロックに含める。承認後に仕様が変わった場合も、コメントを追加したり別Issueを作ったりせず、この同じIssue本文を再度編集して最新の承認済み内容に更新する。テストは承認済み振る舞いモデルから作り、実装結果や内部設計図から作らない。

   引き継ぎ出力には少なくともIssue番号/URL、承認済み仕様が入ったIssue本文、承認時点を示す要約を含める。

## レビュー成果物

GitHubはD2をネイティブ描画しないため、対話中はdevserverで、合意後はIssue本文上のSVGで図を直接見られるようにする。複雑な図は関心事ごとに分割する。

承認済み仕様はIssue本文の正本とし、PR本文やコード差分に仕様を複製しない。設計で振る舞いの不足が見つかった場合はここに戻り、新しい承認内容を同じIssue本文へ反映してから設計判断を見直す。

## 関連

- 振る舞いの承認後は [`design-alignment`](../design-alignment/SKILL.md) で内部設計をモデル化する。
- dev/TDDの振る舞いテストは、この承認済みIssue本文の仕様だけを根拠にする。
