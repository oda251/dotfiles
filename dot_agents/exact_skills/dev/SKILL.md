# 開発

仕様・設計の合意後、実装に入るときに使う。

## 手順

1. 依頼内容と確定済みの仕様・設計、リポジトリの開発手順を確認する。実装に必要な点が不足・矛盾している場合は、振る舞いを推測で決めず依頼元に確認する。
2. 変更する振る舞いに適したテストがあれば、実装前に追加または確認し、未実装の振る舞いで失敗することを確かめる。テストが適さない場合は、別の方法で振る舞いを確認する。
3. 確定済みの仕様・設計に沿って必要な実装を行い、既存のパターンやツールに従う。
4. 関連するテストやチェックを実行し、結果と未解決の問題を確認する。
5. 差分を見直して変更内容と検証結果を報告する。コミットやPRなどの後続作業は依頼内容とリポジトリの手順に従う。
