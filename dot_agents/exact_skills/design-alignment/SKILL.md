# 設計合意

- `spec-alignment` で合意した仕様を読む。未合意なら先に仕様を合意する。
- 既存部品を調査し、事実と提案を分ける。
- 責務・境界・依存・データ所有を自然言語と図で提示する。
- 再利用・改修・新規作成の選択肢とトレードオフを整理する。
- ユーザーの合意前に実装しない。設計で仕様を変更しない。
- 振る舞いの不足や矛盾が見つかったら、`spec-alignment` に戻る。
- 合意した設計図をPR本文に載せ、ソースは折りたたみ節に含める。図ファイルはコード差分に含めない。
- テストは合意した外部振る舞いを対象とし、内部設計の品質は別にレビューする。
