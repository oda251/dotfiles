# 設計合意

外から見える仕様が合意され、実装前に内部設計を検討するときに使う。

## 手順

1. 合意済み仕様が記載されたIssue本文を確認する。未合意、または設計判断に必要な振る舞いが未確定なら、先に `spec-alignment` に戻る。
2. 関連する既存部品とその利用箇所を調べ、確認できた事実と設計案を区別する。
3. 設計案を文章とD2図で示し、必要な選択肢やトレードオフを説明する。
4. `d2 --watch --browser=0 <model.d2>` でレビュー用のdevserverを起動し、指摘を設計案と図に反映して実装前に合意する。設計上の判断で合意済み仕様を変えない。レビュー後はdevserverを停止する。
5. 外から見える振る舞いに不足や矛盾が見つかったら、`spec-alignment` に戻り、同じIssue本文を更新してから設計を見直す。
6. 合意した仕様・設計と実装に必要な情報を、次の実装工程へ引き継ぐ。

## 成果物

- 合意した設計図をSVGとしてPR本文に掲載し、D2ソースを折りたたみ可能な `<details>` に含める。
- SVGは `d2 <input.d2> <output.svg>` で生成し、図ファイル自体はコード差分に含めない。
